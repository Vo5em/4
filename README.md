# Виртуальный бот для исследования стен Bybit

Бот использует публичные рыночные данные Bybit Linear. Он моделирует сделки и не отправляет ордера на биржу.

## Запуск

1. Создайте локальный `.env` на основе `.env.example` и задайте `TELEGRAM_BOT_TOKEN`, `DATABASE_URL` и `ADMIN_USER_ID`. Файл `.env` игнорируется Git.
2. Установите зависимости: `python -m pip install -r requirements.txt`.
3. Запустите приложение: `python run.py`.

При первом запуске создаются таблицы `runtime_state`, `trading_pairs`, `pair_strategy_configs`, `virtual_trades` и `market_prices`. Текущие настройки, включённые для каждой пары стратегии, сделки и последняя наблюдавшаяся цена восстанавливаются из PostgreSQL. Если найдена старая таблица `simbols`, её корректные Bybit USDT-пары добавляются в `trading_pairs`, если там ещё нет такой пары; существующие настройки новых таблиц имеют приоритет. Цена каждой пары сохраняется не чаще одного раза в 5 секунд. Книга заявок и временный поток сделок заново синхронизируются с Bybit после запуска или переподключения.

## Управление в Telegram

Бот отвечает только пользователю `ADMIN_USER_ID` в личном чате. Главная панель показывает режим, подключение рыночных потоков, баланс, ставку, лимит сделок, общий и недельный результат.

- **Пауза входов** отменяет ожидающие входы, а открытые виртуальные сделки продолжает сопровождать.
- **Закрыть только открытые сделки** закрывает текущие позиции по последней цене, оставляет ожидающие входы и продолжает сканирование.
- **Полная остановка** завершает открытые виртуальные сделки по последней полученной цене, отменяет ожидающие входы и останавливает потоки данных.
- При штатном завершении процесса или перезапуске приложения потоки останавливаются, а открытые виртуальные сделки и режим движка сохраняются в PostgreSQL для восстановления при следующем запуске. Это отличается от кнопки полной остановки.
- Ставка, общий лимит и параметры каждой пары редактируются в разделе настроек и сохраняются в PostgreSQL.

Начальные пары можно перечислить в `TRADING_SYMBOLS`. Новые линейные USDT-пары можно добавлять из раздела настроек Telegram; настройки по умолчанию сохраняются в PostgreSQL, а поток запускается сразу, если движок активен.

## Добавление стратегии

Стратегия реализует контракт `TradingStrategy` из `script/strategies.py`: уникальный `strategy_id` и метод `evaluate(context)`, возвращающий список `TradeSignal`. Новую стратегию нужно реализовать и зарегистрировать в `build_strategy_registry()` в `script/strategies.py`; она станет доступна приложению, но автоматически не включится. Включённый список хранится отдельно для каждой пары, настраивается из Telegram и восстанавливается из PostgreSQL. При первом создании конфигурации пары включена `stable_wall_v1`; затем можно отключить все стратегии или выбрать нужные.

Движок зависит от контракта `ExecutionBackend` из `script/execution.py`. Сейчас единственная реализация — `TradeManager`, которая исполняет только виртуальные сделки. В будущем можно добавить отдельный Bybit-адаптер за этим контрактом, сохраняя стратегии и публичный конвейер анализа отдельно. Такой адаптер, авторизация и реальные ордера в текущем проекте отсутствуют.

## Важные ограничения текущей версии

- Результаты виртуальных сделок считаются без комиссий и проскальзывания, кроме цены фактического пересечения стопа.
- Схема новых таблиц создаётся через SQLAlchemy `create_all`. Старые таблицы `orders` и `completad_trades` не переносятся: исходные модели содержат некорректные ссылки на `symbols.id`, поэтому автоматическое сопоставление старой истории небезопасно. Эти таблицы и их данные не удаляются и не изменяются. Старые настройки пользователей тоже не импортируются.
- Реальная авторизация аккаунта Bybit и размещение ордеров не реализованы.

## Проверки

Запустите обычные локальные проверки командой `python -m unittest discover -v`. Для запуска PostgreSQL integration test задайте `RUN_POSTGRES_INTEGRATION=1` и `DATABASE_URL` на локальную одноразовую базу с именем, оканчивающимся на `_test`; этот тест пересоздаёт схему в этой базе. GitHub Actions запускает его с отдельным временным PostgreSQL-сервисом.
